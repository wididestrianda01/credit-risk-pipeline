## Area 2: DFS 0-Column Root Cause

**Question:** Primitive types (mode/any/all) vs Woodwork type inference — which fix strategy?

**User decision:** Diagnose first with a dry run (1000 rows, inspect dtypes)

**Research update:** Root cause identified as **Woodwork type inference** in featuretools 1.31,
not primitive types specifically. Without explicit LogicalType annotations, string/object
columns get typed as Categorical, causing aggregation primitives to produce non-numeric outputs.

**Final decision:** Fix = explicit Woodwork LogicalType annotations in `_build_entity_set()`.
Dry run diagnostic step retained as validation before full run.

## Area 5: Best Practices for DFS with Tree Models

**Research findings (from DFS research agent):**
- Tree models: use correlation dedup only, no IV filtering (IV is for WoE/logistic regression)
- Depth=2 is standard for multi-table credit datasets
- Explicit Woodwork types prevent 0-column bug
- Expected: 150-250 initial DFS features → 50-100 after dedup

**Research findings (from time-feature research agent):**
- Top Gini >0.75 solutions emphasize trajectory features (6m vs 12m DPD rates)
- Streaks (longest consecutive DPD) outperform count/sum of DPD events
- Windowed aggregations at 3m/6m/12m align with credit cycle horizons
- Recency weighting: recent events dominate credit scoring

**Decisions locked:**
- D-03: depth=2, 5 numeric primitives only
- D-04: correlation dedup only, no IV
- D-06: 17 time-window features (full list in CONTEXT.md D-06)
