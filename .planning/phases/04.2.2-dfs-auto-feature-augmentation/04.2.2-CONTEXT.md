<decisions>
## Implementation Decisions

### D-01 — Prerequisite: Rebuild X_tree_raw first
- **Decision:** Phase plan step 0 calls `build_raw_feature_store()` unconditionally.
  Assert shape (307511, 100+) before proceeding.
- **Why:** `X_tree_raw.parquet` is (500, 2) due to test-run overwrite — same trap documented
  in CLAUDE.md. This phase cannot proceed on corrupted data.

### D-02 — DFS 0-column root cause: Woodwork type inference
- **Decision:** Fix by adding explicit Woodwork `LogicalType` annotations inside
  `_build_entity_set()` when adding each dataframe to the EntitySet.
  - Integer ID columns (SK_ID_CURR, SK_ID_BUREAU, SK_ID_PREV): `Integer`
  - String/object columns (CREDIT_ACTIVE, STATUS, NAME_CONTRACT_STATUS, etc.): `Categorical`
  - Float columns: `Double`
  - Boolean flag columns: `BooleanNullable`
- **Why:** featuretools 1.31 uses Woodwork for type inference. Without explicit types,
  string columns get inferred as object-dtype Categoricals, causing aggregation primitives
  to produce object-dtype outputs that the `select_dtypes(include=["number"])` filter then
  drops entirely — resulting in 0 numeric features.
- **Diagnostic step required:** Before fixing, run a 1000-row dry run and print
  `feature_matrix.dtypes.value_counts()` to confirm the dtype distribution and log
  how many columns survive the numeric filter. This informs whether additional fixes are needed.

### D-03 — DFS depth and primitives
- **Decision:** `max_depth=2`, `agg_primitives=["count", "mean", "sum", "std", "num_unique"]`
- **Why:** Brendan Hasz's Home Credit tutorial (same 7-table dataset, 356K rows) used
  max_depth=2 and generated 218 features. Depth=1 misses two-hop relationships
  (e.g. bureau → bureau_balance aggregations). Primitives stripped to numeric-only:
  `mode`, `any`, `all`, `percent_true`, `skew`, `median` removed because they either
  produce non-numeric outputs or duplicate signal from mean/std.
- **Update required:** `_DEFAULT_AGG_PRIMITIVES` constant in `src/auto_features.py`
  from the current 13-primitive list to: `["count", "mean", "sum", "std", "num_unique"]`

### D-04 — DFS filtering strategy
- **Decision:** Correlation deduplication only (threshold 0.90) — no IV filter.
- **Why:** IV filtering requires WoE binning, which is inappropriate for tree models
  (this is the entire motivation for the raw feature pipeline). Trees handle correlated
  features natively through feature importance.
- **Existing code:** `deduplicate_dfs_features()` in `src/auto_features.py` is the correct
  function — use as-is with `corr_threshold=0.90`.

### D-05 — Merge strategy: always merge, skip Gini-gate
- **Decision:** `X_tree_dfs.parquet = pd.concat([X_tree_raw, X_dfs_dedup, X_time], axis=1)`.
  Do NOT call `evaluate_dfs_features()` as a gate.
- **Why:** The phase goal is to produce the combined artifact unconditionally. The Gini
  evaluation gate was designed for a commit/defer context that no longer applies here.
  Gini evaluation happens in the model training phase, not the feature store phase.
- **Deduplication between raw and DFS:** After DFS dedup, also drop DFS columns that
  correlate > 0.90 with any column already in X_tree_raw. This prevents DFS from
  re-generating signals already captured by the hand-engineered raw features.

### D-06 — Time-window features (new scope addition)
- **Decision:** Add a new function `engineer_time_features(data_dir)` in `src/features.py`
  that produces all time-window features listed below. Merged into X_tree_dfs alongside DFS.
- **Why:** Research shows windowed DPD rates (6m vs 12m), trajectory, and streak features
  are the highest-signal additions in top Kaggle solutions (Gini >0.75). These are
  NOT auto-generated by DFS (DFS doesn't know about time windows), so must be hand-engineered.
- **Rationale for "add all":** The user explicitly requested adding all time-related features
  from the research findings. These complement DFS features (which do aggregates across all
  time) with recency-weighted and trend signals.

**Features to implement in `engineer_time_features()`:**

| Feature | Source table | Formula |
|---------|-------------|---------|
| `bbal_dpd_rate_3m` | bureau_balance | fraction of rows with MONTHS_BALANCE ≥ -3 where STATUS not in {C, X, 0} |
| `bbal_dpd_rate_6m` | bureau_balance | fraction of rows with MONTHS_BALANCE ≥ -6 where STATUS not in {C, X, 0} |
| `bbal_dpd_rate_12m` | bureau_balance | fraction of rows with MONTHS_BALANCE between -12 and -7 where STATUS not in {C, X, 0} |
| `bbal_dpd_trend` | bureau_balance | bbal_dpd_rate_6m_mean − bbal_dpd_rate_12m_mean (positive = worsening) |
| `bbal_months_since_last_dpd` | bureau_balance | min months since last row with STATUS not in {C, X, 0}; 999 if never |
| `bbal_recent_max_severity` | bureau_balance | worst numeric STATUS in MONTHS_BALANCE ≥ -6 (0=clean, 1–5=DPD buckets) |
| `inst_months_since_last_dpd` | installments_payments | months since most recent row where DAYS_ENTRY_PAYMENT > DAYS_INSTALMENT; 999 if never |
| `inst_longest_dpd_streak` | installments_payments | max consecutive late payment count per SK_ID_CURR |
| `inst_pct_late` | installments_payments | count(rows where payment late) / count(all rows) per SK_ID_CURR |
| `inst_payment_trend` | installments_payments | OLS slope of (AMT_PAYMENT / AMT_INSTALMENT) sorted by DAYS_INSTALMENT |
| `prev_days_decision_min` | previous_application | MIN(DAYS_DECISION) per SK_ID_CURR (most recent = closest to 0) |
| `prev_days_decision_range` | previous_application | MAX − MIN of DAYS_DECISION (time span of prior applications) |
| `prev_approved_rate` | previous_application | count(NAME_CONTRACT_STATUS == "Approved") / count(all) per SK_ID_CURR |
| `cc_dpd_rate_3m` | credit_card_balance | fraction of rows with MONTHS_BALANCE ≥ -3 where SK_DPD > 0 |
| `cc_dpd_rate_6m` | credit_card_balance | fraction of rows with MONTHS_BALANCE ≥ -6 where SK_DPD > 0 |
| `bureau_days_credit_min` | bureau | MIN(DAYS_CREDIT) per SK_ID_CURR (most recent credit = max/closest to 0; use MIN for oldest) |
| `bureau_credit_age_mean` | bureau | MEAN(abs(DAYS_CREDIT)) / 365.25 — average credit account age in years |

**Notes:**
- All windowed features: missing values (applicants with no records in that window) → -999 sentinel
- STATUS codes in bureau_balance: 0=0DPD, 1=1-30, 2=31-60, 3=61-90, 4=91-120, 5=120+, C=Closed, X=Unknown
- DPD = Days Past Due; STATUS not in {C, X, 0} means delinquent
- Streak calculation: sort installments by DAYS_INSTALMENT, compute run-length encoding of `is_late` boolean

### D-07 — Output path and done condition
- **Output:** `data/processed/X_tree_dfs.parquet`
- **Done condition:** shape (307511, N>155), all columns numeric, no NaN values,
  DFS columns have non-zero variance, index name = SK_ID_CURR
- **Column arithmetic:** X_tree_raw ~155 + DFS dedup ~50-100 + time features ~17 =
  220+ expected columns; >155 threshold is a floor, not a ceiling

### D-08 — Tests required
- Unit tests for `_build_entity_set()` with explicit LogicalTypes (verify no 0-column output)
- Unit tests for `engineer_time_features()` covering each time window, streak logic, sentinels
- Integration test: X_tree_dfs.parquet shape assertion (307511, >155)
- Regression: correlation between any DFS column and X_tree_raw column must be < 0.90

</decisions>

<deferred>
## Deferred Ideas (out of scope for this phase)

- **DFS depth=3:** Exponential feature explosion; defer until after Gini >0.70 target is hit
- **Gini evaluation gate (`evaluate_dfs_features()`):** May be useful in model training phase
  to measure DFS contribution; not needed here since we always merge
- **OLS slope via sklearn LinearRegression for `inst_payment_trend`:** If compute time is
  excessive on 307K rows, fallback to (last - first) / n_observations as a simpler proxy
- **Time-decayed aggregations (exponential decay):** More theoretically correct for recency
  weighting but complex to implement; current 6m/12m windows are a practical approximation

</deferred>
